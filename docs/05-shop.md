# 05. Логика магазина

Всё в `src/lib/` — чистые функции с тестами (`lib.test.ts`).

## Букет как данные (`lib/bouquet.ts`)

```ts
Composition { stems: [{ flower: 'peony', color: 'blush', count: 5 }, …], wrap, ribbon }
```

- **Цена** не хранится, а **считается**: цветы × цены + упаковка + лента +
  работа флориста (`priceBreakdown`). Поменялись цены в справочнике — цена в
  корзине у всех пересчитается сама, старая не «залипнет» в localStorage.
- **Размеры S/M/L** — количества умножаются на 0,6 / 1 / 1,6 и округляются,
  минимум 1.
- **«Уложиться в бюджет»** (`fitBudget`) — жадный алгоритм: убираем по одному
  самый дорогой цветок, пока цена выше бюджета, но каждый вид оставляем хотя
  бы в одном экземпляре — букет не теряет «характер». Возвращает новый состав
  и список убранного, чтобы показать пользователю.
- **Состав в адресе** — `?s=peony.blush.5,eucalyptus.sage.3&w=kraft&r=satin`.
  Адрес может прийти чужой или испорченный, поэтому `fromParams` сверяет
  каждую часть со справочниками и молча отбрасывает неизвестное.
- **Рисунок букета** детерминирован: `seedOf(composition)` — хеш состава,
  он задаёт случайность. Один и тот же букет всегда нарисован одинаково.

## Фильтры каталога (`lib/catalog.ts`)

Адрес — источник правды: `fromSearch(location.search)` → фильтры,
`toSearch(filters)` → адрес. Пустые и значения по умолчанию в адрес не
пишутся — ссылки короткие. Перестановка карточек при фильтрации — GSAP Flip
(хук `useFlip` кита): снимок позиций до изменения, после — карточки
плавно «доезжают» на новые места.

## Корзина и избранное (`lib/store.ts`, `lib/cart.ts`)

Свой стор на 60 строк вместо Redux/Zustand — хватает
`useSyncExternalStore` из React:

```ts
const cart = createStore('lepestok:cart', [], validateCart)
const items = cart.use()               // в компоненте
cart.set((prev) => addItem(prev, x))   // откуда угодно
```

Закрытые баги:

1. В localStorage может лежать что угодно (старая версия сайта, правка
   руками) — всё прочитанное проходит через `validate`.
2. Две вкладки: положили в корзину в одной — счётчик обновился в другой
   (событие `storage`).
3. Приватный режим — хранилище молча работает без сохранения, сайт не падает.
4. `useSyncExternalStore` требует, чтобы `get()` возвращал **тот же** объект,
   пока данные не менялись, иначе бесконечный цикл рендеров. Поэтому состояние
   хранится в переменной, а не читается из localStorage на каждый `get()`.

Одинаковый букет с той же открыткой — не новая строка, а +1 к количеству.

## «Сервер» (`lib/api.ts`, `hooks/useAsync.ts`)

Бэкенда нет, но интерфейс ведёт себя как с настоящим API: задержка сети,
отмена запроса, ошибки. Проверить: `/catalog?fail` — каталог не загрузится;
имя получателя «ошибка» при оформлении — сервер вернёт ошибку поля.
Подключить настоящий бэкенд — заменить тела функций на `fetch`, сигнатуры
оставить.

`useAsync` — загрузка с состояниями `loading → success | error` и «повторить».
Ушли со страницы — запрос отменяется через `AbortController`; ответ на
старый запрос после нового (гонка) игнорируется.

## Формы и доставка (`forms/schemas.ts`, `lib/delivery.ts`)

Схемы в стиле zod (из кита). Интересное:

- **Время — аргумент** (`slotsFor(date, now)`), а не `new Date()` внутри:
  функции чистые, тесты проверяют «сейчас 17:30» без подмены часов.
- **«Сейчас» — в момент проверки**, а не при загрузке страницы: вкладку могли
  оставить открытой на полдня, и утренний интервал уже недоступен.
- Интервал недоступен, если до его начала меньше 2 часов на сборку.
- Даты — по **местному** времени: `new Date('2026-10-04')` — это полночь по
  UTC, и западнее Гринвича получилось бы «вчера».
- Схемы объявлены **вне** компонентов: модуль формы сравнивает опции по
  ссылке, и схема, созданная в компоненте, перезапускала бы его на каждом
  рендере.
