# 01. Архитектура «Лепестка»

Цветочный магазин на React 19 + TypeScript + Vite, собранный на шаблоне
[frontend-kit](README.md#документация-шаблона-frontend-kit). Бэкенда нет —
«сервер» имитируется (см. главу 05), всё остальное как в настоящем проекте.

## Папки

```
src/
  main.tsx        запуск: провайдер кита, роутер, прелоадер, системная тема
  App.tsx         каркас (шапка, страница, подвал), маршруты, переходы
  pages/          страницы; все, кроме главной, грузятся лениво
  components/     шапка, карточка букета, галерея, рисунок букета, ♥…
  modules/        «живые» эффекты по контракту кита: hero, переходы, фон, анимации
  lib/            чистая логика без DOM: цена, фильтры, корзина, доставка — с тестами
  data/           справочники: цветы, оттенки, упаковки, букеты, тексты
  forms/          схемы проверки форм
  hooks/          useAsync — загрузка с отменой и «повторить»
  styles/         SCSS: настройки, каркас, элементы, секции
kit/              шаблон: модули, SCSS, React-адаптер, dev-панель
```

## Три слоя

| Слой | Что делает | Пример |
| --- | --- | --- |
| `lib/` | считает, ничего не знает о React и DOM | `priceOf(composition)`, `fitBudget()`, `slotsFor()` |
| `modules/` | оживляет DOM-элемент: анимации, canvas, WebGL | `heroReveal`, `pageTransition`, `blossoms` |
| `pages/` + `components/` | React-разметка, состояние, связывает всё вместе | `Builder.tsx`, `BouquetCard.tsx` |

Логика в `lib/` — чистые функции: на вход данные, на выход результат.
Поэтому 220+ тестов проверяют цены, фильтры и доставку без браузера.

## Контракт модулей

Все эффекты написаны по одному правилу кита:

```ts
export default function heroReveal(el: HTMLElement, ctx) {
  // …навесить анимации, слушатели, ScrollTrigger
  return { destroy() { /* всё снять */ } }
}
```

В React модуль подключается хуком `useModule` — он вызывает модуль при
монтировании элемента и `destroy()` при размонтировании:

```tsx
<section className="hero" ref={useModule(heroReveal)}>
```

Почему не писать анимации прямо в компонентах: модуль не зависит от React
(тот же код работает на обычной вёрстке), его легко отключить при «меньше
движения» (`ctx.reduced`), а `destroy()` гарантирует, что после ухода со
страницы не останется висящих ScrollTrigger и слушателей.

## Маршруты и ленивые страницы

`App.tsx`: главная импортируется сразу, остальные — через `lazy()`. Код
каталога или конструктора скачивается только при первом переходе туда.
Хитрость: загрузка начинается **во время** анимации перехода (`preload()`),
поэтому к моменту, когда экран залит, код страницы обычно уже готов. Подробно —
глава 03.

## Где хранится состояние

| Что | Где |
| --- | --- |
| Фильтры каталога | в адресе (`?occasion=love&tone=pink`) |
| Состав букета в конструкторе | в адресе (`?s=peony.blush.5,…`) |
| Корзина, избранное | `localStorage` через свой маленький стор (глава 05) |
| Тема | `localStorage` + атрибут `data-theme` (глава 06) |

Адрес — лучшее хранилище для того, чем хочется поделиться: ссылка открывает
тот же фильтр или тот же букет, а «Назад» в браузере работает как отмена.
